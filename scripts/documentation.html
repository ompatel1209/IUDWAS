1. Executive System Overview & Architecture Foundation

The Intelligent University Document & Workflow Automation System (IUDWAS) is a state-of-the-art academic document lifecycle management and multi-level approval orchestration platform engineered for universities and educational institutions.

1.1 Technology Stack Breakdown

Layer / Subsystem Core Technologies Architectural Responsibilities
Client Application (SPA) React 18.3, Vite 6.4.3, TypeScript 5.7, Tailwind CSS 3.4, Lucide Icons, Canvas Confetti Apple Design System UI, responsive glassmorphism aesthetic, JWT session management, document previews, workflow trackers, real-time analytics dashboards.
API Gateway & Core Server Node.js 24 LTS, Express 4.21, TypeScript 5.7 RESTful API routing, centralized JWT authentication, role-based access control (RBAC), multi-tier sliding-window rate limiters, error sanitization.
Persistence & Caching Better-SQLite3 11.8 (WAL Mode), In-Memory Backoff Cache ACID transactional persistence, foreign key cascading, atomic multi-step workflow transactions, sub-millisecond query execution, zero external daemon overhead.
Document Storage & Ingestion Multer, FS Stream Pipelines, Binary Magic-Byte Engine Isolated disk storage outside web root, cryptographically random UUID naming, deep header inspection (%PDF-, PNG, JPEG, PK..), sandboxed download headers.
Intelligence & OCR Subsystem Tesseract OCR Bridge, Simulated NLP Classifier & Search Full-text document indexing, automated category detection, contextual summaries, semantic search queries, interactive assistant chatbot.

1.2 Core Role-Based Access Control (RBAC) Hierarchy

User Role Permitted Actions Operational Scope & Security Boundary
SUPER_ADMIN Full system control, User management, Department configuration, Workflow template authoring, Global Audit log lookup, System settings modification. Global University-wide scope across all academic and administrative departments.
DEPT_ADMIN Manage department faculty & students, create departmental workflows, review & approve departmental workflow steps, manage department document repository. Department-scoped isolation (restricted strictly to their assigned academic department).
FACULTY Upload documents, create tags, submit workflow instances, approve/reject assigned review steps, delegate approvals, search departmental records. Department and individual scope. Can view public and departmental documents.
STUDENT Upload personal student documents (transcripts, petitions), submit workflow approval requests, track real-time workflow status, download owned files. Strict Individual Owner Scope (IDOR protected; forbidden from viewing other students' confidential files).

4. Security, Validation & Rate Limiting Architecture

4.1 Tiered Rate Limiting & DDoS Shield

The system enforces 5 distinct rate-limiting tiers. On authentication endpoints, an in-memory exponential backoff store mitigates brute-force attacks by increasing delays upon consecutive failures rather than imposing an irreversible hard account lockout.

Exponential Backoff Formula:
Delay(seconds) = min(baseSeconds * 2^(failedAttempts - freeAttempts), maxSeconds)
For default settings: 5 free attempts -> 2s -> 4s -> 8s -> 16s -> 32s ... capped at 1800s (30 minutes).

4.2 Strict Input Schema Validation (Zod)

Every HTTP request body, URL path parameter, and query string is validated against strict Zod schemas with .strict() to prevent field pollution or mass assignment attacks. Any malformed type, invalid regex, out-of-range integer, or unrecognized key is immediately rejected with HTTP 400 VALIDATION_ERROR and structured issue diagnostics.

4.3 File Upload Security & Magic-Byte Engine

Uploaded documents are inspected in binary format immediately post-upload:

  • Extension Whitelist: Only .pdf, .docx, .doc, .xlsx, .xls, .jpg, .jpeg, .png, .tiff, .txt allowed.
  • Executable Header Block: Binary scans reject Linux ELF (0x7F 'ELF'), Windows PE ('MZ'), Mach-O, shell shebangs (#!/), and embedded script tags.
  • Isolated Storage: Uploaded files are written to /uploads outside public web root with cryptographically random UUID names.
  • Sandboxed Downloads: Downloads include Content-Disposition: attachment, X-Content-Type-Options: nosniff, and Content-Security-Policy: default-src 'none'; sandbox.

4.4 Information Leakage Prevention & Error Sanitization

All client error responses pass through sanitizeClientErrorMessage. Internal absolute file paths, database constraint names, SQL query strings, and V8 runtime stack traces are completely stripped before returning to the user, while comprehensive diagnostic traces are preserved in server logs.
